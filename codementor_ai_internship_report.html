CHAPTER 1
INTRODUCTION

1.1 PROJECT OVERVIEW & PURPOSE

In the modern era of software engineering, technical recruitment processes for product-based tech companies heavily rely on evaluating candidates on Data Structures, Algorithms (DSA), and analytical problem-solving. Computer science undergraduates frequently face a learning gap when transitioning from dry, academic textbooks to complex, fast-paced technical coding interviews. Traditional methods of learning include writing code in compilers, reading documentation, and solving mock questions in environments that lack structured mentorship.

This summer internship project presents CodeMentor AI, an interactive web-based AI coding assistant custom-designed to bridge this gap. CodeMentor AI is built using a modern full-stack web architecture leveraging a React frontend client and a Java Spring Boot backend server. The backend securely connects to the OpenAI API (utilizing GPT-4o mini via JSON schema response mode) to act as a simulated expert interviewer. The system provides students with an 8-stage interactive learning sequence rather than a flat, text-based solution copy, allowing students to progressively understand constraints, formulate brute force ideas, receive hints, examine optimized Java code, debug failures, review related core interview questions, and summarize key data structures lessons.

1.2 OBJECTIVES OF THE INTERNSHIP

The primary objectives achieved during the course of this summer internship project include:

  • To design and develop a responsive, minimal, dark-themed user interface in React.js that complies with modern visual web standards, utilizing glassmorphic panels, gradient badges, and layout collapse controls.
  • To construct a scalable backend REST API using Java 17 and Spring Boot (Spring Web MVC) that handles request routing, data processing, and communication with external artificial intelligence interfaces.
  • To implement robust application security using Spring Security and JWT (JSON Web Tokens) to authenticate users, manage authorization filters, encrypt credentials using BCrypt, and establish stateless API request validation.
  • To integrate JPA (Java Persistence API) and Hibernate ORM for mapping database entities and managing transactions dynamically with PostgreSQL as a persistent database store.
  • To implement a conversational history logging system that captures, pins, renames, and deletes session state securely without introducing memory leaks or excessive payload sizes.

1.3 SCOPE OF THE SYSTEM

The scope of CodeMentor AI focuses on creating a reliable, localized development and testing platform for DSA learners. The frontend web UI is structured as a three-column dashboard: the collapsible left sidebar manages active chat sessions and page transitions; the center panel serves as the main content viewport hosting the landing screens, chat consoles, history management panels, or user profiles; the right sidebar displays statistics, streak counts, solved task categories, and activity logs.

The backend server handles input sanitization, validates token headers using a Custom once-per-request filter, delegates structured prompt payloads to the OpenAI completions endpoint using RestTemplate, maps JSON responses directly to specific DTO objects, and commits transactions to a PostgreSQL relational database. The platform is bounded to local deployment, acting as a modular template that can easily scale to containerized production hosts using Docker and Kubernetes.

CHAPTER 2
STUDY OR SURVEY

2.1 EXISTING SYSTEMS LITERATURE REVIEW

An inspection of currently available platforms for DSA practice reveals several popular tools, each with distinct advantages and disadvantages:

1. Online Evaluators (e.g., LeetCode, HackerRank):
These platforms excel at grading code correctness through automated test suite runs. However, they are highly transactional. If a student gets stuck on a dynamic programming problem, the platform does not guide the student through conceptual steps. Students are forced to look at discussion forums or solutions, which often results in copy-pasting code without acquiring true intuition.

2. General Purpose LLMs (e.g., ChatGPT, Claude):
General purpose AI platforms can explain code concepts conversationally. However, their outputs are unstructured and highly variable. One prompt might yield a complete optimized solution directly, while the next might provide a brief, text-only hint. For DSA prep, this unstructured format is counter-productive because students require a step-by-step interview-mimicking flow to build logic.

3. Static Educational Portals (e.g., GeeksforGeeks, Tutorialspoint):
These portals offer excellent reference articles containing code snippets across various languages. Yet, they lack personalization. The student cannot interact with the code, modify inputs to observe output changes, or get tailored hints based on their specific logic mistakes.

2.2 LIMITATIONS OF THE EXISTING SYSTEM

The critical drawbacks of existing systems can be summarized as:

  • Lacking Guided Tutoring: Most platforms provide the full solution immediately, preventing the candidate from building the code step-by-step (e.g., analyzing brute force complexity first).
  • Absence of Progress & Streak Dashboards: Generic LLMs do not keep track of specific problem categories solved by the user, nor do they record user milestones.
  • No Session Persistence: Casual web-based compiler prompts do not persist conversations or let users search and filter history under a secure account.
  • Unsecured endpoints: Simple AI wrapper backends often lack standard authentication protocols like JWT, exposing API keys to leaks or massive abuse.

Before undertaking the implementation, a three-way feasibility analysis was conducted to ensure project viability:

1. Technical Feasibility: The technology stack (React, Java 17, Spring Boot, Spring Security, JPA, PostgreSQL) represents mature, widely supported environments. Integration with the OpenAI API is achieved using standard HTTP client calls (RestTemplate) and Jackson JSON deserializers. Developing the frontend using Vite guarantees fast builds and hot module replacement. Therefore, the project is technically feasible.

2. Economic Feasibility: The development environment uses open-source software, including PostgreSQL database server, Node.js, and Java OpenJDK. The only operational cost involves the OpenAI completions API billing. Since the platform utilizes the cost-efficient `gpt-4o-mini` model, API costs per query are fractions of a cent, making the platform highly cost-effective and economically viable.

3. Operational Feasibility: The system is designed to run in standard modern web browsers. The minimal dark-themed interface mimics tools that computer science students already use daily. The application requires zero installation on the user's local machine, ensuring high user adoption and simple operational deployment.

  • Responsiveness: The visual layout must collapse to a single column format on mobile viewports.

CHAPTER 5
SYSTEM ENVIRONMENT

5.1 JAVA & SPRING BOOT FRAMEWORK

Java is chosen as the core backend programming language due to its type safety, platform independence, robust memory management, and extensive enterprise framework support. Spring Boot is an extension of the Spring framework that eliminates boilerplate XML configurations, introducing starter dependencies and embedded runtime servers (such as Tomcat) to allow developers to build production-grade standalone applications instantly.

In CodeMentor AI, Spring Boot leverages **Spring Web MVC** to handle RESTful endpoint routing, mapping incoming HTTP POST requests containing prompts to Java DTO beans using the Jackson serialization library. It also coordinates dependency injection, binding service singletons such as `OpenAiService` to REST controllers like `ChatController` and `HistoryController` dynamically.

5.2 POSTGRESQL & HIBERNATE ORM

PostgreSQL is a powerful, open-source object-relational database system that supports advanced SQL querying, relational integrity, and high transactional safety. Hibernate is an Object-Relational Mapping (ORM) framework that acts as a bridge between the object-oriented Java classes and the relational PostgreSQL tables.

In this project, Hibernate automatically handles table creations and schema updates from entity class annotations (e.g., `@Entity`, `@Table`, `@Id`). **Spring Data JPA** simplifies repository implementation by automatically generating SQL queries from method declarations (e.g., `findByIsPinnedTrueOrderByCreatedAtDesc()`), reducing the developer's need to write complex SQL statements.

5.3 REACT.JS & VITE BUILD ENVIRONMENT

React.js is a component-based JavaScript library developed by Meta for building interactive user interfaces. It uses a Virtual DOM to compute UI diffs and re-render components efficiently when states change.

In CodeMentor AI, React manages visual states like collapsible sections, active views, user input fields, and asynchronous loading states. **Vite** is used as the frontend build tool. Vite utilizes native ES modules (ESM) to serve source files during development, ensuring fast hot module replacement (HMR) and compiling highly optimized assets for production in seconds.

CHAPTER 6
IMPLEMENTATION

6.1 AUTHENTICATION & SECURITY MODULE (JWT)

Securing access to the AI services is handled by a stateless JWT token verification workflow. When a user submits registration details, they are validated, and the password is encrypted using a cryptographic BCrypt hashing algorithm before insertion into PostgreSQL. Upon login, the user's credentials are authenticated by the `AuthenticationManager`. On success, the server builds a compact JSON Web Token signed with a HS256 key: 

// JwtUtils snippet for JWT signing
public String generateJwtToken(Authentication authentication) {
    UserDetailsImpl userPrincipal = (UserDetailsImpl) authentication.getPrincipal();
    return Jwts.builder()
            .subject(userPrincipal.getUsername())
            .issuedAt(new Date())
            .expiration(new Date((new Date()).getTime() + jwtExpirationMs))
            .signWith(key())
            .compact();
}

For subsequent requests to `/api/chat` or `/api/history`, the `JwtAuthenticationFilter` intercepts the request, parses the header (`Authorization: Bearer `), checks the signature, and sets the authenticated principal inside Spring Security's context.

6.2 8-STEP INTERACTIVE CHAT MODULE

The chat system connects user queries to the OpenAI endpoint. To enforce a consistent, structured output format suitable for student learning, the system prompts the AI to respond in a strict JSON structure matching the DTO `ChatResponse.java`. 

// Java DTO mapping the 8-Stage response structure
@Data
public class ChatResponse {
    private String topic;
    private String difficulty;
    private String step1ProblemUnderstanding;
    private String step2BruteForceConcept;
    private String step3ThinkBeforeOptimize;
    private String step4Hint;
    private String step5OptimalJavaCode;
    private String step6DebuggingChallenge;
    private List<InterviewQuestion> step7InterviewQuestions;
    private String step8LearningSummary;
}

The prompt commands the model to return JSON structure conforming to the above fields. The React frontend reads this payload and populates distinct interactive CSS panels. If the backend is offline, the React application falls back to showing local mock cards so the user experience is not disrupted.

6.3 CONVERSATION ARCHIVE & HISTORY MODULE

The conversation history module permits CRUD actions. In the database, the `conversations` table stores the topic, difficulty, prompt text, pin status, and creation timestamp. The frontend `HistoryPage.jsx` fetches data using: 

// React Fetching inside HistoryPage
const fetchHistory = async () => {
  try {
    const res = await fetch('http://localhost:8080/api/history');
    if (res.ok) {
      const data = await res.json();
      setConversations(data.map(c => ({
        id: c.id,
        title: c.topic,
        pinned: c.pinned || c.isPinned,
        date: new Date(c.createdAt),
        difficulty: c.difficulty
      })));
    }
  } catch (err) {
    console.error("Fetch failed", err);
  }
};

Using PATCH methods, users can toggle the `isPinned` state and edit the `topic` name. DELETE queries permit purging old conversations.

CHAPTER 7
TESTING

7.1 TESTING METHODOLOGIES APPLIED

To verify the reliability, security, and accuracy of the CodeMentor AI system, multiple testing methodologies were systematically applied:

1. Unit Testing: Individual backend components were verified using JUnit 5 and Mockito. In particular, `OpenAiService` was tested by mocking the RestTemplate bean to return mock JSON payloads, ensuring that JSON parsing and error handling operate correctly under bad gateway responses.

2. Integration Testing: REST endpoints like `/api/history` and `/api/auth/login` were tested end-to-end. We verified that creating a conversation successfully commits a record in PostgreSQL, and registering a duplicate user returns a 400 Bad Request error.

3. Security Testing: Tested API routes to confirm that accessing `/api/chat` without a valid Bearer token in the request header returns a 403 Forbidden error. Verified that password fields stored in database tables are fully encrypted and unreadable.
