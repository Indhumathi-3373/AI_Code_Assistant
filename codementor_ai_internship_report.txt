CHAPTER 1: INTRODUCTION

1.1 PROJECT OVERVIEW AND PURPOSE

In the modern software engineering landscape, recruitment processes for product-based technology companies heavily evaluate candidates on Data Structures, Algorithms (DSA), and analytical problem-solving. Computer science undergraduates frequently face a significant learning gap when transitioning from dry academic textbooks to complex, fast-paced technical coding interviews. Traditional methods of learning include writing code in compilers, reading documentation, and solving mock questions in environments that lack structured, interactive mentorship.

This summer internship project presents CodeMentor AI, an interactive web-based AI coding assistant custom-designed to bridge this gap. CodeMentor AI is built using a modern full-stack web architecture leveraging a React frontend client and a Java Spring Boot backend server. The backend securely connects to the OpenAI API (utilizing GPT-4o mini via JSON schema response mode) to act as a simulated expert interviewer.

Instead of presenting flat, text-based solution codes immediately, the system provides students with an 8-stage interactive learning sequence. This structure allows students to progressively understand constraints, formulate brute force ideas, receive hints, examine optimized Java code, debug failures, review related core interview questions, and summarize key data structures lessons.


1.2 OBJECTIVES OF THE INTERNSHIP

The primary objectives achieved during the course of this summer internship project include:

1. Designing and developing a responsive, minimal, dark-themed user interface in React.js that complies with modern visual web standards, utilizing glassmorphic panels, gradient badges, and layout collapse controls.
2. Constructing a scalable backend REST API using Java 17/21 and Spring Boot (Spring Web MVC) that handles request routing, data processing, and communication with external artificial intelligence interfaces.
3. Implementing robust application security using Spring Security and JWT (JSON Web Tokens) to authenticate users, manage authorization filters, encrypt credentials using BCrypt, and establish stateless API request validation.
4. Integrating JPA (Java Persistence API) and Hibernate ORM for mapping database entities and managing transactions dynamically with PostgreSQL as a persistent database store.
5. Implementing a conversational history logging system that captures, pins, renames, and deletes session state securely without introducing memory leaks or excessive payload sizes.


1.3 SCOPE OF THE SYSTEM

The scope of CodeMentor AI focuses on creating a reliable, localized development and testing platform for DSA learners. The frontend web UI is structured as a three-column dashboard: the collapsible left sidebar manages active chat sessions and page transitions; the center panel serves as the main content viewport hosting the landing screens, chat consoles, history management panels, or user profiles; the right sidebar displays statistics, streak counts, solved task categories, and activity logs.

The backend server handles input sanitization, validates token headers using a Custom once-per-request filter, delegates structured prompt payloads to the OpenAI completions endpoint using RestTemplate, maps JSON responses directly to specific DTO objects, and commits transactions to a PostgreSQL relational database. The platform is bounded to local deployment, acting as a modular template that can easily scale to containerized production hosts using Docker and Kubernetes.


CHAPTER 2: STUDY OR SURVEY

2.1 EXISTING SYSTEMS LITERATURE REVIEW

An inspection of currently available platforms for DSA practice reveals several popular tools, each with distinct advantages and disadvantages:

1. Online Evaluators (e.g., LeetCode, HackerRank):
These platforms excel at grading code correctness through automated test suite runs. However, they are highly transactional. If a student gets stuck on a dynamic programming problem, the platform does not guide the student through conceptual steps. Students are forced to look at discussion forums or solutions, which often results in copy-pasting code without acquiring true intuition.

2. General Purpose LLMs (e.g., ChatGPT, Claude):
General purpose AI platforms can explain code concepts conversationally. However, their outputs are unstructured and highly variable. One prompt might yield a complete optimized solution directly, while the next might provide a brief, text-only hint. For DSA prep, this unstructured format is counter-productive because students require a step-by-step interview-mimicking flow to build logic.

3. Static Educational Portals (e.g., GeeksforGeeks, Tutorialspoint):
These portals offer excellent reference articles containing code snippets across various languages. Yet, they lack personalization. The student cannot interact with the code, modify inputs to observe output changes, or get tailored hints based on their specific logic mistakes.


2.2 LIMITATIONS OF THE EXISTING SYSTEM

The critical drawbacks of existing systems can be summarized as:

1. Lacking Guided Tutoring: Most platforms provide the full solution immediately, preventing the candidate from building the code step-by-step (e.g., analyzing brute force complexity first).
2. Absence of Progress and Streak Dashboards: Generic LLMs do not keep track of specific problem categories solved by the user, nor do they record user milestones.
3. No Session Persistence: Casual web-based compiler prompts do not persist conversations or let users search and filter history under a secure account.
4. Unsecured endpoints: Simple AI wrapper backends often lack standard authentication protocols like JWT, exposing API keys to leaks or massive abuse.


2.3 PROPOSED SYSTEM ARCHITECTURE ADVANTAGES

CodeMentor AI addresses these deficiencies by establishing a structured, secure, and persistent workspace. The system enforces an 8-stage interactive response sequence:
Stage 1: Problem Understanding - Clarifies input bounds, corner cases, and constraints.
Stage 2: Brute Force Concept - Formulates the simplest working solution.
Stage 3: Think Before Optimize - Asks conceptual questions to prompt optimization.
Stage 4: Hints - Provides targeted hints without revealing code.
Stage 5: Optimal Java Code - Presents fully commented, clean Java code blocks.
Stage 6: Debugging Challenge - Asks questions on edge cases or code walk-throughs.
Stage 7: Q and A FAQ - Curated list of alternative approaches and interview questions.
Stage 8: Learning Summary - Recap of data structures and patterns applied.

By wrapping these conceptual steps in visual accordion elements in the UI, students are encouraged to "Think before they look." Security is ensured by hashing credentials using BCrypt and validating API routes with Spring Security. The integration of PostgreSQL ensures that user progress, streaks, profiles, and histories are securely saved and can be searched or filtered on-demand.

3.2 SOFTWARE REQUIREMENTS SPECIFICATION (SRS)

3.2.1 Functional Requirements

1. User Account Management: Users must be able to register accounts and log in securely. The system must issue a JWT token upon successful authentication.
2. Interactive DSA Mentor: The chat interface must submit user queries to the backend and render responses in 8 distinct collapsible sections.

3. Reliability: If the backend database or AI API is unreachable, the system must fail-safe to mock data options to preserve usability.
4. Responsiveness: The visual layout must collapse to a single column format on mobile viewports.


3.3 UML DIAGRAMS

Use Case Model:
The system actor "User" interacts with the frontend client. The client triggers AuthController for registration and login operations. Once authorized, the user triggers ChatController to start DSA mentoring sessions, and HistoryController to load, rename, pin, or delete conversation archives.

Class Structure:
The class structure defines a User entity containing credential strings and role attributes. The User maps to a UserProfile tracking streaking integers and problem-solving collections. The Conversation entity models stored logs containing topic strings, difficulty classifications, raw prompt texts, pin flags, and message counters.

Sequence Flow:
1. User enters prompt in React UI.
2. Client forwards a POST request to /api/chat containing Bearer tokens in headers.
3. Security Filter interceptor validates token signatures.
4. ChatController passes prompts to OpenAiService.
5. OpenAiService queries the Completions endpoint using configured templates.
6. Received completions are parsed into ChatResponse entities, committed to PostgreSQL, and sent back as HTTP 200 payloads.
7. Client renders the 8 learning accordions.

CHAPTER 5: SYSTEM ENVIRONMENT

5.1 JAVA AND SPRING BOOT FRAMEWORK

Java is chosen as the core backend programming language due to its type safety, platform independence, robust memory management, and extensive enterprise framework support. Spring Boot is an extension of the Spring framework that eliminates boilerplate XML configurations, introducing starter dependencies and embedded runtime servers (such as Tomcat) to allow developers to build production-grade standalone applications instantly.

In CodeMentor AI, Spring Boot leverages Spring Web MVC to handle RESTful endpoint routing, mapping incoming HTTP POST requests containing prompts to Java DTO beans using the Jackson serialization library. It also coordinates dependency injection, binding service singletons such as "OpenAiService" to REST controllers like "ChatController" and "HistoryController" dynamically.


5.2 POSTGRESQL AND HIBERNATE ORM

PostgreSQL is a highly reliable relational database system. It supports relational integrity and concurrent transaction management. Hibernate is an Object-Relational Mapping (ORM) framework that acts as a bridge between the object-oriented Java classes and the relational PostgreSQL tables.

In this project, Hibernate automatically handles table creations and schema updates from entity class annotations. Spring Data JPA simplifies repository implementation by automatically generating SQL queries from method declarations, reducing the need to write complex SQL statements.


5.3 REACT.JS AND VITE BUILD ENVIRONMENT

React.js is a component-based JavaScript library developed by Meta for building interactive user interfaces. It uses a Virtual DOM to compute UI diffs and re-render components efficiently when states change.

In CodeMentor AI, React manages visual states like collapsible sections, active views, user input fields, and asynchronous loading states. Vite is used as the frontend build tool. Vite utilizes native ES modules (ESM) to serve source files during development, ensuring fast hot module replacement (HMR) and compiling highly optimized assets for production in seconds.


CHAPTER 6: IMPLEMENTATION

6.1 AUTHENTICATION AND SECURITY MODULE (JWT)

Authentication uses Spring Security filters with stateless token generation:
The User model defines the DB representation with encrypted password storage. The AuthController handles register and login endpoints, generating a token using the Jwts builder package with a key derived from decoders. An interceptor filter parses Authorization headers, checks Bearer prefix states, validates token signatures, and injects authenticated principal contexts into Spring Security configurations.


6.2 8-STEP INTERACTIVE CHAT MODULE

The Chat interface uses structural JSON completion configurations to feed details to the client accordion views. The OpenAI completable prompt commands the model to output JSON structures containing specific fields matching Java ChatResponse DTO definitions. This ensures clean structural parsing. If connection errors arise, the React UI uses a fail-safe configuration load of mock card data so usability is preserved.


6.3 CONVERSATION ARCHIVE AND HISTORY MODULE

History logs are requested on mount from the /api/history endpoint. The UI displays searchable list panels. Each conversation card triggers state updates:
- Pin toggles trigger PATCH requests to /api/history/{id}/pin.
- Renames trigger PATCH requests to /api/history/{id}/rename.
- Deletions trigger DELETE requests to /api/history/{id}, updating the client view state.


6.4 PERFORMANCE AND PROFILE MODULE

The profile module gamifies DSA practice. It plots streaking counters, XP badges, difficulty counts, and contribution calendar grids. React dynamically updates these elements from the user profile service, rewarding consistency and providing a visual breakdown of completed Easy, Medium, and Hard milestones.
